# Vue-компоненты

- Только `<script setup lang="ts">`. Порядок блоков: `<script setup>` → `<template>` → `<style>` (стиль — только если без него никак, см. styling.md).
- Props — type-based: `defineProps<{ team: Team }>()`. Значения по умолчанию — через деструктуризацию (Vue 3.5+): `const { limit = 5 } = defineProps<...>()`, а не `withDefaults`.
- Emits типизировать: `defineEmits<{ select: [id: number] }>()`.
- Двусторонняя привязка — `defineModel()`, а не пара prop + `update:` emit вручную.
- Ссылки на DOM — `useTemplateRef('name')`.
- Имена компонентов — PascalCase и из нескольких слов (`TeamCard`, а не `Card`). Views называть с суффиксом `View`.
- `v-for` всегда с `:key` по стабильному id из API, не по индексу. Не ставить `v-if` на тот же элемент, что и `v-for`: фильтровать через `computed`.
- Производные данные считать в `computed`, а не в методах, которые вызываются из шаблона.
- В шаблоне — простые выражения; если логика длиннее одной строки, выносить в `computed` или функцию.
- View не делает `fetch` сам: данные получает через composable (`useMatches` и т.п.), а тот берёт их из store.
- Каждый экран, который грузит данные, обрабатывает три состояния: загрузка, ошибка (включая 429 — превышение лимита), пустые данные.
- Интерактивные примитивы (табы, дропдауны, диалоги, комбобокс поиска) брать из Reka UI, а не писать свои: в Reka UI уже есть доступность и клавиатурная навигация.
- Логотипам команд — `alt` с названием команды; кнопкам без текста — `aria-label`.
