# Рабочий процесс и инструменты

- Разделение работы (см. CLAUDE.md): логику (`<script setup>`, services, types, stores, composables, router, конфиги) пишет пользователь по инструкциям Claude. Разметку (`<template>`) и Tailwind-стили в `.vue` пишет Claude сам, не трогая `<script setup>`. В инструкциях пользователю не давать задания по вёрстке и стилям — после его шага логики Claude сам обновляет шаблон.
- Версии стека новее, чем данные обучения могут покрывать: Vue 3.5, Vue Router 5, Pinia 4, Tailwind 4, Reka UI 2, Vite 8, TypeScript 6. Прежде чем давать API-советы по этим библиотекам, сверяться с документацией через MCP **context7**.
- Проверка UI: dev-сервер (`npm run dev`, http://localhost:5173) + MCP **chrome-devtools** — скриншот, консоль, сетевые запросы (видно 429 и ответы прокси).
- Перед тем как считать задачу готовой: `npm run type-check`, `npm run lint` и проверка в браузере. Автотесты в проекте не пишем — не предлагать их.
- Prettier запускается хуком автоматически после правок Claude; конфиг — `.prettierrc.json` (без `;`, одинарные кавычки, ширина 100).
- Секреты: `.env.local` не читать и не выводить; в примерах — только `.env.example`.
- Скиллы проекта (`.claude/skills/`): `/next-step` — что делать дальше, `/new-screen` — план экрана, `/api-explore` — ответ API → типы, `/vue-review` — ревью кода пользователя, `/check` — все проверки, `/ui-check` — проверка страницы в браузере. Предлагай подходящий скилл, когда он уместен.
